# POPY：保留画质的运算图优化

后续在严格无损版上增加了 [遮罩公共表达式批处理](MASK_BATCHING.md)。本页和两种旧输出作为上一轮基线保留；最新运行时包为 `POPY_fullbody_maskbatched.zip`。

本轮保留原始全身模型 `output/POPY_fullbody/`，另行生成两个候选版本。所有 39 个参数、58 个 motion3、24 个 exp3、六张原分辨率纹理、ArtMesh 顶点/三角形、UV、变形器及遮罩引用均保留。没有简化几何、缩小纹理、缩减角度范围或减少表情。本轮不生成新 CMO3，不修改源 Blender 工程或 Ayagami 上游。

## 两种编译模式

`exact` 模式把 Glue 程序视为带读写依赖的计算图。对每个 `(ArtMesh, vertex)` 建立 RAW、WAR 和 WAW 依赖，按拓扑顺序批处理端点及标量字段完全相同的操作。每个顶点上的有依赖运算次序不变；保留原浮点系数、参数网格和 pair 次序。哈希不是近似判断，字段签名包含完整 float32 值。

一个容易遗漏的问题是：在当前浮点实现中，即使源端权重为 0，`lerp(A, A, t)` 也可能产生舍入误差。因此只有常量兼容性恰为 1 的零权重侧被视作只读，其他源顶点仍参与写依赖。不能仅根据实数公式把它当作无副作用操作。

`precision` 模式额外使用实数恒等式：

```
lerp(lerp(B, A, 1), t) = lerp(lerp(B, A, t), 1)
```

只对 `NativeG_` 三维骨架的常量、单向 Glue，将 float32 常量 `t` 从 Glue 兼容性移到目标 pair 权重，再做依赖图批处理。全部权重仍在 0～1；参数驱动的标量曲线不变。脸部、头发、眼睛、发饰等遮挡程序不做这种因子转移。

此模式改变浮点累计舍入，**不宣称与旧模型逐位一致**。它必须用独立保存的 Blender 源顶点投影验收，不能仅以相邻模型差异很小来证明画质。打包程序要求全部已测姿态的骨架几何 RMSE 和最大误差均不高于原版，最大误差小于 0.01 像素，脸/眼/眉/头发/发饰顶点保持一致，并要求精确模式通过逐位验证。

这是数学因式分解与公共计算批处理，没有用低阶拟合替代未验证的高维面部残差。若继续用 SVD/Tucker/曲面拟合压缩面部关键形，应保留残差，另做遮挡边界与连续参数检查；本轮没有将这种有损拟合混入模型。

## 复现

需要本机完整 POPY 全身基线、362 姿态参考、81 组 Blender 源几何、已安装依赖及原工程构建工具。仓库不附带角色资产。运行：

```powershell
python -m popy.performance_review all
```

依次构建工具、生成两份独立 IR、导出实际 MOC、复用原动作/表情、验证、渲染、计时、生成报告、运行完整测试并打包。原始 `POPY_fullbody` 不覆盖。JDK/Blender/基线准备见主 README。可用 `build|rig|export|cases|validate|images|benchmark|report|test|package` 单独重跑；`validate --mode exact` 启用严格逐位判定。低层 IR 编译也可单独调用：

```powershell
python -m popy.performance_opt --mode exact --out artifacts/perf_opt/exact_rig
python -m popy.performance_opt --mode precision --out artifacts/perf_opt/precision_rig
```

运行时入口：

- `output/POPY_fullbody_optimized/POPY.model3.json`：精度优化版。
- `output/POPY_optimized_exact/POPY.model3.json`：逐位一致版。
- `delivery/POPY_fullbody_optimized.zip` / `delivery/POPY_fullbody_bitexact.zip`：对应资源包。
- `artifacts/perf_opt/report/index.html`：原版/新版对照和全部误差数据。
- `benchmarks/popy/fullbody/performance_optimization.json`：公开数值证据。

## 验证和计时边界

1,803 个参数组合包含原 362 姿态、39 参数各 17 点扫描、256 个固定随机种子的全参数组合及全部 58 动作各 9 个时间点。外部 Rust 程序同时加载两份真实 MOC，调用固定、未修改的 Ayagami 公共 driver，逐顶点检查，包括隐藏矩阵和遮罩载体；同时检查参数范围、UV、索引、遮罩、剔除、纹理页及求值后的透明度/深度/颜色。隐藏矩阵使用很大增益，隐藏载体的绝对像素差不可当作可见表面误差。

GPU 图像比较重新渲染原版、精确版、精度版各 362 姿态。另以 81 组独立 Blender 顶点投影检查真实骨架误差，图像仍与 Blender 参考计算轮廓 IoU、MAE、SSIM。舍入修正会改变少量亚像素光栅结果，因此精度版不以“图片逐位相同”描述；精确版必须图片逐位相同。

性能单独运行同一组挥手/大笑/步行 60 姿态，每次排除 5 帧预热，以 ABBA 次序重复。`--timing-only` 仍做完整参数求值、原尺寸遮罩及 GPU 渲染和同步，省去下载与 PNG 写盘；输出目标像正常播放器一样复用并逐帧清空。参数设置、prepare、渲染编码和 GPU 提交/等待分别记录。另以相同序列单独测量 CPU driver，反转两份模型的求值先后次序，排除图像回归并发过程中的干扰。桌面没有隔离；它不是稳定实时帧率承诺。不要把不同姿态集合或精度验证并发过程中的计时当作最终性能比较。最初逐帧分配输出纹理的计时也保留在本地 `timing_allocated_target.json`，不隐去其中长帧。

完整结果以生成的公开数值文件为准。当前模型仍有大量遮挡载体和密集排序/面部关键形，优化不会消除原有复杂遮挡、布料/接触及官方编辑器兼容性限制。

## 本机结果（2026-11-04）

RTX 5080 Laptop GPU、原生 Vulkan、固定 Ayagami 提交；不代表浏览器 WebGPU 的帧率。

| 指标 | 原版 | 精度优化版 |
|---|---:|---:|
| Glue | 394,221 | 249,055（−36.82%） |
| MOC 字节数 | 565,880,768 | 550,678,592 |
| 同序列 CPU driver 中位数 | 69.72 ms | 54.19 ms（−22.28%） |
| 参数设置至 GPU 完成中位数 | 193.40 ms | 178.72 ms（−7.59%） |
| 同序列完整帧平均数 | 274.27 ms | 315.52 ms |
| 同序列完整帧 P95 | 1,105.32 ms | 1,880.89 ms |
| 81 姿态身体/四肢最大源顶点重投影误差 | 0.035868 px | 0.003569 px |
| 362 姿态平均前景 MAE | 0.01214351 | 0.01213758 |

全部 81 姿态的骨架几何 RMSE 和最大误差均改善；1,803 姿态中脸、眼、眉、头发和发饰网格的顶点保持原值，透明度/深度/颜色相同。精度版会改变少量身体亚像素光栅结果，单姿态 MAE 最差增加 0.00000458，IoU 最差减少 0.00002309，SSIM 最差减少 0.00009813；不宣称每个图像指标都改善。上述 0.003569 px 是身体/四肢保留源顶点的误差，不代表原有面部残差已经消除。

**完整渲染没有得到稳定加速。** 中位数下降，但本次精度版平均数和 P95 上升；已保留两次计时的原始数据。分阶段计时显示长帧主要集中在 GPU 提交/等待，不能由此单独断言是显存、驱动或其他桌面负载造成。当前原生模型有 1,490 个不同的遮罩集合，1,980 个受遮罩 ArtMesh，单集合最多 398 个来源；GPU 遮罩成本仍是后续重点。不能用 CPU 改善掩盖 GPU 长帧。

严格无损版将 Glue 减到 359,392，MOC 为 562,166,336 字节。1,803 姿态共 1,148,467,728 个顶点比较全部逐位一致，362 个渲染姿态像素一致；同序列 CPU driver 为 69.05→66.29 ms，约下降 3.99%。其完整帧中位数 195.50→195.40 ms，几乎不变，因此也不宣称已解决实时渲染问题。**需要严格保留原画面时优先使用 bitexact 包。**

96 项 Python 测试及 7 项 Rust 测试通过。已验证真实 MOC 加载、参数求值、网格渲染及资源引用；没有官方 Cubism Core/Editor 验证。

下一步最值得做的是在保留相同屏幕像素采样的前提下，对运行时遮罩做整数像素边界裁剪、图集复用及更细的失效传播，再评估带残差的头部几何张量分解。单纯降低遮罩分辨率、删遮挡片或删关键形不满足本项目的画质要求。
