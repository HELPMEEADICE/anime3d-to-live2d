# POPY 面部穿透遮盖修复

本轮处理耳边皮肤白点、脸颊发际线细缝、脸内异常头发三角形、被遮住的鼻线，以及极端张嘴时牙齿被口腔壳盖住的问题。它是此前衣领修复上的真实几何更新，不经过 PSD，也没有把姿态烘焙成贴图序列。

本地最新入口为 `output/POPY_face_fixed/POPY.model3.json`，交付包为 `delivery/POPY_face_fixed.zip`。逐姿态报告为 `artifacts/face_repair/report/index.html`；公开数值位于 `benchmarks/popy/face_repair/`。旧的衣领、头发包和平衡版 CMO3 均保留，**不包含本轮修复**。

## 根因与实现

同一幅图里的异常可以有相反原因：大块皮肤分片的排序盖过了前发，或者弯曲头发分片的平均排序盖进了脸部。直接整体前置头发会损伤眼睛和星星发饰。鼻线另有真实的独立黑色源几何；它原来被皮肤覆盖，不能与错误露出的深色头发混为一谈。

`popy.face_attribution` 输出原始三角形的真实投影、相机深度与 ArtMesh 排序。Rust `face_conflicts` 用重心深度光栅化找出互相矛盾的覆盖区域，保留源 ArtMesh 和三角形编号。筛查覆盖 105 组头部姿态 × 9 组身体姿态 × 3 组稀疏表情，共 2,835 组。这是几何筛查，**不是 2,835 次独立 Blender/GPU 图像验收**；它不考虑全部已有遮罩，只负责提出保守候选。

对候选源三角形及其一环邻域，使用共享边、局部法线和支撑平面误差分组。当前配置为 0.3mm 厚度容差、法线点积下界 0.8、最多 24 个原始三角形。原 ArtMesh 保留为隐藏的完整求值主网格。新可见分片在原有接缝 Glue 和所有姿态/表情求值结束后，精确复制主网格角点；可见 UV、原始三角形、来源编号和形变映射都保留。

新分片放回原主网格附近的渲染列表位置，以保留与眼睛、发饰等对象在整数绘制顺序相同时的先后关系。只复制数值排序而把全部分片追加到列表末尾，会产生新的边缘错误。

前景源三角形按目标分片的三维支撑平面裁剪，再通过原生反向遮罩和参数化重心 Glue 表达。已有实测表明，原始 POPY 的整个头发与脸部在中性表情下随头骨刚性运动：105 姿态的头部相对拟合误差小于 1µm。因此头部/身体刚性旋转由原网格承担；裁剪交点只需存局部眼睑、嘴部和笑眼等表情的稀疏组合，避免复制完整姿态张量。支撑平面及表情中间值仍然属于近似。

牙齿使用稳定的口腔层级，并由真实皮肤、嘴唇/口腔、头发等前景几何裁剪。它们的可见部分仍随真实三维牙齿顶点及张嘴/嘴形参数变化。 源面部材质实测为双面显示，因此口腔深度遮罩保留双面几何；另复用已排除后脑的真实前表面皮肤，建立随形变连续变化的口腔开口遮罩。这样避免近共面的牙齿/唇部支撑平面误差在掠射角下放大。前表面共享遮罩没有使用图片轮廓。鼻线只调整其已审计独立部件的排序，不对整张脸或整头头发加全局前置。

### 遮罩和导出成本

原先的后发遮罩反复引用 398 个身体/服装源网格。新分片使这组来源在许多不同遮罩上下文中重复绘制。本轮将其合并为可共享的原生透明辅助网格，角点仍由原求值网格驱动，三角形绕序不变。只有确认所有相关纹理 Alpha 完全不透明时才允许这种合并；透明素材会明确拒绝该优化。单个辅助网格限制为 60,000 顶点。

额外实现并实测了把所有局部前景来源也打包的方案。两原型的 218 姿态逐像素一致，但全打包增加约 195 万个复制顶点，文件更大、头部运动更新更慢，因此交付默认关闭 `pack_local_sources`，仅保留共享的大型重复遮罩。新 Glue 先精简不变轴和冗余标量关键值；最终 `compact_forms` 还会使用已有的 0.05px 估算预算压缩标量曲线。该预算依赖来源直径和 Warp 放大率估计，不是全部连续组合的严格误差上界，完整统计保留在 `scalar_grid_compression`，并通过实际图像回归验收。原有 Glue 完全保留。

独立 GPL 导出器的运行时导出在构建 PuppetModel 后释放大型 JSON 树，并不再复制 MOC3 本来不会写入的编辑器 `userData` 字符串；完整来源映射仍在 Rig IR 中。该变更重新导出了衣领基线，MOC 字节与旧文件完全相同。CMO3 分支仍保留原始编辑器数据。

## 实机验证

主验收为 218 组**独立 Blender 渲染与真实 Ayagami MOC GPU 渲染**：

- 两个用户截图的精确参数。
- 水平 7.5°、垂直 7.5° 的 117 点网格。
- 63 个连续头部 X/Y/Z 样本，共 60 对相邻帧。
- 24 组眨眼、嘴形、张嘴、眉毛和笑眼组合。
- 12 组头部与身体极值组合。

另外重跑既有 264 姿态的实际加载/渲染、77 姿态眼睛/脸部/发饰 ID 图像验收，以及 79 姿态衣领 ID 图像验收。额外数值探针比较原始主网格与可见分片角点/排序，并用独立 IR 插值交叉检查原生遮罩 Glue。264 姿态的加载渲染记录不能替代另外两组的图像质量指标。

源 ID 图保留纹理 Alpha 和真实遮挡，统计脸部 ROI 内错误露出、误遮挡、小型连通误差及连续变化；报告同时列出 1px 和 3px 容差。口腔另外增加 38 个姿态的独立牙齿/口腔/皮肤 ID 渲染，作为主要口腔验收；这些参数是主验收集合的子集，不另算 38 个独立姿态。独立投影牙齿边界中的白色纹理诊断只作辅助，易受贴图过滤和抗锯齿影响，不能代替源 ID 判断。原始数据、最坏姿态和回归退步全部保留在报告中。

### 最终实测数值（2026-11-04）

下列是同一参考、同一 ROI 的累计像素数，默认允许 1px 边界误差；不是错误发生次数。

| 指标 | 衣领基线 | 面部修复后 |
|---|---:|---:|
| 皮肤错误露出 / 缺失 | 11,651 / 32,915 | 9,618 / 25,589 |
| 头发错误露出 / 缺失 | 12,965 / 16,171 | 5,775 / 13,548 |
| 鼻线缺失 | 1,456 | 84 |
| 头发超过 3px 的缺失 | 9,073 | 9,246 |
| 连续帧错误变化像素 | 10,646 | 8,446 |
| 38 姿态牙齿缺失 / 错误露出 | 1,395 / 16 | 2 / 65 |
| 衣领 79 姿态错误露出 / 缺失 | 350 / 580 | 350 / 513 |

截图右转姿态的耳边白点、脸颊细缝和鼻边头发小块分别为 4→0、8→0、7→0。77 姿态眼睛和发饰的缺失/错误露出指标保持原值。牙齿总错误从 1,411 降到 67，但错误露出增加 49 像素；头发大于 3px 的缺失也有增加。原生遮罩 Glue 与独立 IR 插值最大差 0.000161px，可见分片与原始主网格角点最大差 0.000138px。55 项 Python 和 7 项 Rust 测试全部通过。

最终模型有 4,216 个 ArtMesh（包括隐藏求值主网格与遮罩）、592,837 个顶点、717,747 个三角形、280,855 个 Glue、19 个参数、8 个变形器、约 309 万个几何关键形，六张 2048² 纹理；MOC 为 572,064,000 字节。218 姿态含 GPU 完成及读回的中位耗时为 185.71ms，基线为 32.49ms；修复后最慢样本为 3,405.91ms。这是在有其他应用驻留的非隔离桌面环境中测量，不能等同于专用 Live2D 宿主帧率，也不能由驻留进程推断其实际 GPU 负载。质量改善伴随显著成本增加。

过程耗时与进程树 RSS 见公开 `performance.json`。初次 218 姿态、两组原始源对照及 38 口腔 ID 的 Blender 参考渲染由独立后台命令完成，未记录其进程树峰值内存；缺失值没有补造。各阶段反复执行，不能把累计实验耗时当成一次全新转换总耗时。

## 已知限制

本轮不能证明所有实数参数组合零穿模。支撑平面、三点表情裁剪场、原有投影插值和少数边界处仍有残差。

此前 Blender 的毛发碰撞修正会改变原始三维头发轨迹，而转换基线主要以遮罩近似这些位移。极端组合下，下颌附近仍有较大的毛发/脸部差异。对两个最坏姿态另渲染了未加碰撞修正的原始 Blender 快照；差异明显缩小，支持这一诊断。不能把这些剩余像素都宣称为已修复的排序问题。

进一步提高牙齿平面精度并增加局部关键值的原型使分片数从 55 增到 178，生成成本显著增加，已中止且未获得验证 MOC，不作为交付默认。共享口腔开口遮罩用一个辅助网格取得了更合适的精度/成本平衡。

下一步最值得做的是保留细分来源对应关系，将**实际经过碰撞修正的三维毛发轨迹**传入 IR，并对非刚性头部/身体耦合使用误差驱动的低秩残差拟合；同时研究共享参数化绘制组，避免每个角点跟随分片重复携带整组几何/排序关键形，并压缩遮罩上下文。当前高质量模型的文件体积和实际验证耗时均明显高于衣领基线，具体数据见报告，不能宣称适合所有实时宿主。

本轮只更新真实 `.moc3/.model3.json/.cdi3.json` 与六张纹理。目标为 Cubism 5.0，已由固定版本 Ayagami 解析、求值和渲染；没有生成新的 CMO3，也没有进行官方 Cubism Editor/Core 兼容性验证。

## 复现

依赖与之前的 POPY 转换一致：Windows、Python、Rust、JDK 26、Blender 5.2.2 LTS、固定的 PSD2Live/Ayagami 源码，以及已经审计并完成衣领修复的本地资产。

```powershell
$env:JAVA_HOME = 'C:\lib\java'
$env:JAVA_OPTS = '-Xmx12g -XX:+UseG1GC -XX:+ExitOnOutOfMemoryError'
python -m popy.face_repair all
```

本次各阶段实际分别执行并反复验证，未把一次未执行的完整 `all` 命令描述为已通过。CLI 提供 `prepare|rig|export|reference|validate|regress|report|test|package`；`prepare` 会重建包含内存修复的独立导出器。修改配置或资产后应重新从 `prepare` 开始。

所有 Blender 操作使用独立后台进程和快照。实时 Blender MCP 本轮仍未连接成功，没有更改用户打开的工程，也没有覆盖两份源 `.blend`。源码、数值记录公开；角色模型、纹理、渲染和交付 ZIP 仅保留在本地，资产再分发许可尚未确认。GPL 导出器与中立 Python/Rust 核心继续保持进程与许可证边界；未向 Ayagami 上游提交任何内容。
