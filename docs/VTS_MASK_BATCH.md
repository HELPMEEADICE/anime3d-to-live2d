# 减少每帧遮罩提交：不透明覆盖集合合批

本轮交付 `delivery/POPY_VTS_MaskBatch.zip`，相对 `POPY_VTS_Overlap` 优化完整帧耗时，不新增几何拟合误差，不降低纹理或遮罩分辨率。冻结模型的旧复合动作拟合误差保留。**这是原生 Ayagami DX12 的实测收益，尚非 VTube Studio 实机结果。**

## 数学依据和实际变换

此前将可见网格兼作遮罩来源，因此即使两个网格能用于同一遮罩，也无法直接合并：主画面需要各自的深度、透明度和遮罩成员关系。

新转换器把遮罩用途分离为隐藏代理。每个代理只拼接父级、参数轴、关键值、完整主关键形坐标以及 BlendShape 参数/中性/空形模式一致的几何程序；UV 和原有有向三角形逐项保留。遮罩代理不参加主画面的颜色合成，透明度恒为零，不带自身遮罩，不增加 Glue。源网格自身的裁剪、绘制深度及 RGB 不进入其原始遮罩覆盖计算。

本资产的六张贴图，每一个 alpha 字节均为 255。在原始遮罩绘制中，每个有覆盖的光栅样本因此写入完全覆盖值，遮罩是三角覆盖集合的并集：

```
C1 ∪ C2 = C2 ∪ C1
(C1 ∪ C2) ∪ C3 = C1 ∪ (C2 ∪ C3)
C ∪ C = C
```

这允许按几何程序重排遮罩来源，并将全不透明的纹理页替换为另一个全不透明页。采样点的覆盖集合、三角绕向、剔除方式和每个顶点的实际浮点运算仍相同；最终遮罩过滤使用相同分辨率。**这不是一般半透明 alpha 合成的重排规则**：Python 构建器和 Rust 原生检查器分别读取真实纹理，发现哪怕一个非 255 的来源 alpha 即拒绝使用该模式。

每个候选遮罩列表展开代理后，必须与原列表的来源多重集合完全相等，不允许插入外国来源或漏掉牙齿/脸部遮罩。代理引用同一个网格的完整几何，不以采样图像的近似轮廓替代原始几何。

生成代理后，删除不再被引用、主/BlendShape 透明度始终为零且没有自身裁剪的 96 个旧来源副本；释放原来源的遮罩身份后，再做 127 次严格同状态、同深度程序的相邻网格合并。主画面的顶点程序和有效绘制顺序保持。80 个遮罩上下文、39 参数、58 动作、24 表情、牙齿修复及纹理字节保留。

## 实测

固定未修改的 Ayagami `0d1d7aa3efe57b1b363b72e672e353c52a9c15d6`，RTX 5080 Laptop GPU，原生 DX12。画布及每组遮罩均为 768×1024；同一设备、同一 60 个姿态交替执行 4 轮，每模型预热 5 帧、测量 240 帧。完整帧从参数设置到 GPU 完成，含准备、编码和提交同步，不含图像下载/PNG。两个模型同时驻留，桌面未隔离。

| 指标 | Overlap | MaskBatch |
|---|---:|---:|
| 完整帧中位数 | 31.496 ms | **29.794 ms** |
| 完整帧均值 | 31.271 ms | **29.423 ms** |
| 完整帧 P95 | 36.335 ms | **33.594 ms** |
| 准备阶段中位数 | 17.816 ms | 16.936 ms |
| 编码阶段中位数 | 2.402 ms | 2.096 ms |
| GPU 提交/等待中位数 | 11.682 ms | 10.987 ms |
| CPU Driver 中位数 | 2.088 ms | 2.040 ms |
| ArtMesh | 2,641 | 2,473 |
| 主 ArtMesh 关键形 | 108,270 | 102,602 |
| 顶点 | 170,693 | 185,669 |
| 三角形 | 149,318 | 167,318 |
| MOC 字节 | 83,511,744 | 88,136,256 |
| 重复单模型峰值 RSS 中位数 | 448.80 MiB | 448.59 MiB |

中位帧耗时降低约 **5.4%**，P95 降低约 **7.5%**。独立重复的同设备配对测试为 31.254→29.344 ms，改善约 6.1%。准备和提交均减少，并非通过只测 Driver 来代替完整帧。

全部 80 个上下文的静态来源绘制数之和从 1,017 降为 207（约 −79.6%）；实际某一帧只绘制其中正在使用、被更新的上下文，不将该静态比例宣称为帧耗时下降比例。

代价是 55 个隐藏代理和部分几何重复，净增加 14,976 个顶点、MOC 增加约 4.62 MB（5.5%）；它不是文件最小的版本。内存按 ABBA BAAB 运行 8 个独立单模型进程、相同 65 姿态，含加载/预热，不写图片；基线范围 448.38–454.64 MiB，候选 444.75–449.47 MiB，**中位数基本持平，不宣称有稳定内存降幅**。单次 362 图片进程峰值曾为 526→657 MiB，受驱动/图像瞬时分配影响，报告保留该数据，内存结论使用重复测量。

最初仅按连续来源建立代理的候选没有稳定提速：新增网格的准备成本抵消了绘制减少。因此交付版使用经过不透明证明的集合合批，并清理被释放的旧来源，而非仅增加代理。

## 画质与兼容边界

- 1,803 姿态、334,761,207 次保留/代理顶点比较，float32 位模式零差异。检查每个 UV、每个有向三角形、代理可见性以及主画面的深度/外观。
- 362 个全分辨率 RGBA 结果逐像素一致。资源摘要确认纹理、动作、表情、CDI 和运行时配置字节不变。
- 4 个新增无资产测试通过，包括拒绝单个半透明像素、阻止剔除/中性形模式不同的合并、顶点上限拆分。另 11 个既有相邻合批/严格遮罩测试通过；新增 Python Ruff 检查通过，Rust 检查器 release 构建通过。未声称新的全仓库或远程 CI 验收。
- 目标仍为 Cubism 5.0/MOC v5、零 Glue、2 个 Rotation 变形器。没有新的 CMO3；没有官方 Core、Cubism Editor 或 VTS 实机验收。原生运行时的数据不能推算 VTS 的帧率。
- VTS 继续使用 256 masks、每组至少 512×512。原包保留可回退。
- 部分内部 ArtMesh 已合并。逐网格自定义配置可能需重设。运行时通过自定义功能单独禁用原来源网格，或换成带透明像素的贴图时，代理也需同步重建；交付保证覆盖本包原始资源与参数控制。

## 复现和许可证

需上一轮冻结 IR/资产、用例及构建好的独立 GPL 导出器：

```powershell
cargo build --release --locked --manifest-path rust/Cargo.toml -p popy-validate --bins
python -m popy.mask_proxy all
```

阶段可单独执行 `build|export|timing|validate|memory|report|package`。构建读取 `artifacts/overlap_layout/rig`，输出到专用 `artifacts/mask_proxy` 和 `output/POPY_VTS_MaskBatch`，不修改 Blender 原工程或旧交付。打包要求输入模型/映射/用例/资源摘要匹配几何与像素验证、独立计时和重复内存结果，且完整帧中位数至少改善 3%。位置池继续使用字节去重和可用的重叠共享。

实现位于 MIT 的 `popy/mask_proxy.py`，格式导出继续通过独立 GPL 进程，没有把 GPL 格式代码混入独立模块；Ayagami 上游不修改、不提交。GitHub 只同步代码、说明及数字报告，角色模型与贴图不公开上传。
