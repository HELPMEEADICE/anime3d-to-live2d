# POPY 动作细化：翻掌、连贯运动与侧向腿部控制

本轮针对首版全身动作的三个实际问题：手掌侧对镜头、逐关键点停顿，以及侧向髋关节范围和动作缺失。入口仍为 `output/POPY_fullbody/POPY.model3.json`；重新导出的资源通过 `delivery/POPY_fullbody.zip` 交付，三维动作保存在独立 `delivery/POPY_fullbody.blend`。原始源工程不覆盖。

## 新控制与动作

- `ParamForearmLTurn` / `ParamForearmRTurn`：−100～100°，默认 0。绕实际前臂局部 Y 轴旋转；左右符号单独校准。在附带的屈肘展示姿态中，正值约 80～90° 使掌面朝向相机。肩、肘、腕改变时，朝向也随三维骨架改变，没有把手掌贴图强制前置。
- `ParamLegLSpread` / `ParamLegRSpread`：从原来的 0～15° 扩展到 −25～35°。负值向内交叉，正值向外侧摆。仍由真实髋关节局部 Z 轴驱动，并保留左右相反符号；`ParamLeg*Swing` 继续负责前后摆，两者可组合。
- 保留原 37 项控制的标识符，新增两项翻掌，总计 39 项。已有的挥手、指向、握拳、抬腿、伸展、思考、惊讶及原地步行重新编排，附加左右 `palm_show`、`leg_side`、`side_step` 和循环 `side_sway`，总计 22 段 motion3；16 个表情继续保留。

L/R 指角色解剖学左右。正面画面的右手侧对应角色 L。建议先播放 `palm_show_L/R` 检查翻掌，使用 `leg_side_L/R` 检查独立侧摆，`side_step_L/R` 检查两腿配合，`side_sway` 查看反复左右运动。

## 动作曲线和三维绑定

旧导出曲线给每一段 Bezier 的两端都设置零速度。即使多个关键点沿同一方向变化，中间也会停下。现在使用加权调和切线构建单调三次 Hermite 曲线，再转换成 Cubism 原生受限 Bezier；相邻段共享切线，循环首尾在取值相同时共享速度。保持单调与取值范围，转折点仍允许自然减速。这保证 C1 速度连续，不保证 C2 加速度连续，不能以它单独证明动作自然。

`popy/motion_design.py` 独立保存编排：肩部先做小幅准备，肘部跟随抬起，前臂再翻掌，腕摆稍晚；结束时逐项回收。点指先转眼/头，再伸臂和伸指；握拳先屈肘，再收指。原地步行补充反相摆臂、肘腕滞后、膝踝摆动和小幅上身配合。细小活动是显式可编辑曲线，不依赖随机抖动。

翻掌加入原生矩阵图，几何继续使用每 0.5° 的单参数旋转字段，表达连续多关节组合。配置中的较稀 `keys` 用于绘制顺序采样，不能与几何旋转精度混同。为了控制新维度的规模，肩、肘、手势的排序采样适度减少；它是遮挡近似，需要用图像回归检查，不能凭几何误差小就认定排序正确。

## 本地复现和检查

已有首版 POPY 数据与构建工具时：

```powershell
python -m popy.fullbody all
python -m popy.fullbody frames --motion wave_L --expression smile --fps 15
python -m popy.fullbody frames --motion leg_side_L --fps 15
python -m popy.fullbody frames --motion side_sway --fps 15
python -m popy.fullbody frames --motion walk_in_place --fps 15
```

新参数的极值、未采样值、翻掌对照及侧摆动作加入 Blender / Ayagami 对照和实际 MOC 顶点探针。独立重开 Blender 工程时额外检查左右翻掌和侧抬腿动作。源骨架检查使用腕、食指根、小指根定义掌面三角形，报告其朝向和投影面积，并检查足部的真实横向位移。实际 MOC 顶点误差另行对照，不能用三维源几何测量替代运行时检查。

本机保留首版模型、动作和预览于 `artifacts/motion_refine/before/`。生成新预览后执行 `python -m popy.motion_review`，输出掌面/侧摆/曲线数据、概览和相同时间轴的挥手前后动画；该可选对照需要首版备份。完整报告仍在 `artifacts/fullbody/report/index.html`。公开数值保存到 `benchmarks/popy/fullbody/motion_refinement.json`，角色图像和模型不提交 GitHub。

## 剩余限制

本轮完成 238 个图像姿态、45 组实际 MOC 顶点探针，保留源顶点最大投影误差 0.03587 px。独立重开 Blender 的 12 个检查点最大差为 0 m。挥手中段 10 个左右手样本的掌面朝向指标约 0.925～0.978，掌面三角形投影面积从约 35～45 px² 增至约 309～327 px²；它是骨骼标志点测量，实际手掌渲染另外放大展示。23 项全身测试、全项目 78 项 Python 测试和 7 项 Rust 测试通过。

模型为 5,450 个 ArtMesh、636,976 个顶点、745,170 个三角形和 5,439,363 个 ArtMesh 关键形，MOC 为 565,880,768 字节。新姿态集合的求值至 GPU 完成中位耗时为 289.13 ms；首版和新版姿态集合不同，不能直接以各自总报告中位数判断版本性能变化。因此另外用完全相同的首版挥手参数序列对照：排除前 5 帧后，首版/新版中位数分别为 257.60 / 240.22 ms，P95 为 320.45 / 391.00 ms。桌面未隔离，尾部存在波动；两版运行成本都很高，没有宣称已经达到实时流畅播放。

相同序列计时可在已保留首版备份和动作报告时执行 `python -m popy.motion_review --benchmark`。该对照隔离共享姿态的版本成本，不代表新增翻掌编排的全部成本。

侧步是有明显横向腿部运动的关节动作，没有新增根节点行走位移、足底接触 IK 或地面锁定；不能视为具有可靠落脚的运动系统。手指未新增接触求解或独立的张指自由度。衣袖、裙子依旧使用源蒙皮，没有布料碰撞；极端内收、交叉或手贴身体时仍可能穿插。手/头发接触也未加入模拟。

只对固定 Ayagami 运行时验证；本轮没有新 CMO3，也没有官方 Cubism Editor/Core 验证。更自然的运动仍需结合实际预览继续调节节奏和幅度。
