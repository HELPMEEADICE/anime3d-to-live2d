# 睫毛、眉毛与颈部头发的几何遮挡修复

本轮使用已有的独立 `POPY_source.blend`：首次尝试 Blender MCP 时当前实例未连接，所有新增参考仍由后台 Blender 5.2.2 LTS 实际生成，没有修改用户原工程或覆盖源快照。

## 几何与原生模型

审计确认睫毛是 `M_Face` 内的独立连通曲面，和眼白、皮肤、口腔共用对象；眉毛是 `M_Brow`。`config/surface_visibility.json` 记录实际组件，不把整个 Face 当作皮肤。角色命名和组件编号不是跨模型假设，替换源数据会触发指纹检查。

主睫毛和眉毛按真实三角形连通性、全部局部表情极值的平面误差与法线方向细分。最大深度散布 0.55 mm、最多 12 个三角形、组内法线点积至少 0.8。新分片重新计算自己的三维相机深度，不能沿用旧曲面的平均深度。颈部错误归属到原始头发三角形后，Rust 使用八三角形预算细分相应头发、领口与皮肤区域。

细线的稳定绘制层次由前景遮罩补充：遮罩从真实皮肤、眼白、口腔、头发及配饰裁出。局部支撑平面在目标最靠前顶点之外留 0.1 mm 容差，保守保留合法可见部分。口腔也是必要遮挡源：只用外层皮肤时，闭眼睫毛仍会从张开的嘴部孔洞漏出。

裁剪产生的每个点保留原始遮挡三角形的重心对应。原生 Glue 先单向复制原顶点，再执行两次插值，实现任意凸重心坐标。所有源侧权重均为零，不反向移动真实曲面。Glue 强度使用原生连续参数网格；局部眼/眉表情用 0 / 0.5 / 1 键，颈部相对头部控制用 5×3×3 键。原模型已求值的头部、身体和表情顶点由所有遮罩共享，不为每个遮罩重复存储整套几何关键形。

相同的原顶点/共享边对应轨迹会合并；同形强度曲线归一化后共享 Glue。生成后的裁剪多边形必须在姿态域中实际投影到目标附近，才保留其拓扑；只检查裁剪前的大三角形会产生大量无关顶点。初始辅助网格坐标保持在小数值范围，完全复制后的状态避免浮点相消。

## 稀疏选择与验证

先用 201 个姿态定位残差，再把真实运行时像素归属到原始三角形，得到 `surface_critical.json` 和 `neck_refinement.json`。第二轮归属还检查错误像素下所有重叠的源三角形，修复遮住上层睫毛后、下层睫毛再次露出的情况。图像仅用于选择误差较大的三维区域，不用于生成轮廓网格或替代原始拓扑。默认 `hybrid` 策略只对这些关键区域启用局部深度裁剪。

最终新增 42 个连续眨眼和 21 个连续眉毛组合，合计 264 个表面可见性姿态；新增 63 个样本没有用于选择修复三角形。Blender 使用真实深度生成 RGB ID：红为眉毛、绿为睫毛、蓝为头发，其他表面为黑色。Ayagami 加载另一个真实 MOC，几何、参数、遮罩、原始纹理 alpha 完全相同，仅颜色改变；每个语义类使用独立纹理页，避免共享 UV 污染诊断。

指标分别允许 1px 与 3px 边界误差，颈部 ROI 随源颈部顶点投影移动。它们同时包含位置插值误差，不能直接当作排序错误个数。既统计漏出，也统计原本可见却被遮掉的区域。普通着色对比和原来的 165 姿态眼部/接缝回归另行保留。

`native_glue_check.py` 独立插值 IR 标量网格，和实际导出 MOC 在 Ayagami 中求值的辅助网格逐顶点比较，包括未用于选区的连续眨眼样本。这比只检查文件头或参数清单更严格。

`field_compression.py` 删除不影响曲线的轴和共线中间键，也支持根据源网格姿态直径、父 Warp 的最大伸缩与焊接余量估算的亚像素预算进行精简。每条曲线预算 0.025 px，每个裁剪点最多两条可变曲线；0.05 px 是优化预算估计，不是所有连续姿态的严格证明。压缩后的 MOC 重新执行全部图像与原生顶点回归。原始可见曲面不受该优化移动，源侧 Glue 权重保持零。重复调用不再次累计近似误差。

`runtime_delta.py` 对保存的前一次原生求值和最终模型逐顶点比较：264 姿态中辅助遮罩最大变化 0.00876 px，可见曲面最大差异 0.000069 px，后者处于原生浮点误差量级。测试同时检查该实测预算；原始前一次求值不存在时，不虚构这项比较。

## 运行

```powershell
python -m popy.cli rig
python -m popy.cli export
python -m popy.cli validate
python -m popy.cli report
python -m popy.cli visibility
python -m popy.cli surfaces
python -m popy.cli test
python -m popy.cli package
```

源快照、相机、参考案例和渲染配置未变时，可以分别使用 `popy.visibility_regression --reuse-reference` 与 `popy.surface_runner --reuse-reference`。完整 `run.ps1` 默认重新生成参考。修复区域配置带源数据指纹；更换模型应重新审计和归属，而不是继续使用 POPY 的三角形编号。

## 实际边界

支撑平面仍是曲面的保守近似；有限参数键之间的裁剪交点并非解析三维求交。颈部裁剪系数假定共同身体旋转，主顶点仍使用真实蒙皮关键形，极端混合蒙皮和未采样组合有残差。当前压缩仅验证了正交相机与不透明遮挡纹理，透明裁片与透视需要额外实现，不能直接套用。没有声称消除了所有遮挡错误，也没有进行头发的三维碰撞模拟。

更密集的逐分片深度遮罩及颈部平面细分也实际试过，但运行成本明显增加，改进不足以全部进入默认配置。相关产物保留在 `artifacts/feature_*`，默认输出以最终回归结果为准。

新增遮罩使编辑工程的曲线图规模明显增加，10 GiB 堆仍不足；最终平衡版在 16 GiB 堆下实际写出约 203 MB CMO3，独立读回需要 24 GiB 最大堆。CLI 默认写入最大堆 16 GiB、验证 24 GiB；直接执行导出器默认最大堆 24 GiB。`JAVA_OPTS` 与 `POPY_CMO_VERIFY_JAVA_OPTS` 可分别覆盖。较小机器应只生成质量版运行时（`export --no-cmo`），不能保证在低内存机器上完成编辑工程。释放已读 XML 内容的实验仍未使 16 GiB 读回通过，未纳入默认代码。

CMO3 已单独通过导出器自身库重新读取，核对参数、遮罩、静态与动画 Glue；官方 Cubism Editor 兼容性仍未验证。GPL 导出器维持独立进程边界，Ayagami 上游未修改或提交内容。
