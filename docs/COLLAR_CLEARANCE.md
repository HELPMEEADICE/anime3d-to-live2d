# POPY 脖子与衣领遮挡修复（2026-11-03）

用户截图对应 `ParamAngleX=15, ParamAngleY=11, ParamBreath=0.5`。在上一轮肩颈头发质量版中复现：蒙皮后的脖子皮肤排在前衣领之上，出现粉色块和锯齿缺口。同姿态 Blender 深度渲染中没有该错误，因此本轮修正转换后的遮挡表达，保留上一轮 Blender 头发避碰工程和原始工程。

## 实测

79 个专项姿态包含截图、附近 24 个角度、两条各 21 帧的连续俯仰/水平转头，以及 12 个头身极值组合。两版模型对比同一份 Blender 参考，使用真实脖子顶点投影包围盒加 5px 的 ROI、1px 边界容差；数值包含几何插值误差。

| 截图姿态误遮挡 | 0 | 0 |

错误露出减少约 **93.2%**，误遮挡增加 7px，约 **1.2%**。连续帧指标包含插值偏差，不能等同于纯排序跳变计数。运行成本增加，仍不是轻量成品。

另外实际求值、渲染此前 264 表情姿态与 77 头发姿态，共 341 个；对 77 姿态重新导出眼睛/脸部/星星发饰诊断 MOC 并渲染，三类指标与前版逐项相同。全部可见几何、关键形二进制内容、绘制顺序、非颈部遮罩保持原值。独立 Glue 求值与真实 Ayagami 顶点最大误差约 `0.000081px`，检查 102 个辅助网格的拓扑与遮罩引用。

42 项 Python 测试及 `popy-geometry` 的 2 项 Rust 测试通过；新增无资产几何测试纳入 GitHub CI。未将这些测试解释为所有连续姿态都无瑕疵。

## 实现

`config/collar_clearance.json` 用源空间区域定位 22 个小脖子分片，实际每片不超过 8 个原始三角形。遮挡者从原始 `M_Top/M_Skirts/M_Bow/M_Necktie` 几何选取，不能按对象名把 `M_Skirts` 简单理解为只有裙子：当前资产的该对象还包含前领口。

复用并提取原有深度遮罩构建器，旧头发入口保持原有覆盖策略。针对脖子使用完整 7×5×3=105 个真实头部三轴样本，在每个小片的三维支撑平面前方裁剪衣领三角形，计算连续变化的重心坐标。将遮罩压缩为 21 个不可见辅助 ArtMesh 和 18,027 个原生 Glue。裁剪顶点跟随原始衣服网格，权重由头部参数驱动，身体动作仍由其原始蒙皮投影控制。遮罩使用原生反向裁剪，不修改全局排序，不加预渲染帧。

## 重复执行和交付

在已经完成原始转换与 `python -m popy.hair_repair all`、具有匹配 POPY 本地资产的工作目录运行：

```powershell
python -m popy.collar_repair all
```

可分别执行 `prepare / rig / export / reference / validate / report / test / package`。本轮实际分阶段运行并核对产物，未额外宣称重新执行过整条 `all` 命令。

- `output/POPY_neck_fixed/POPY.model3.json`：本轮质量模型入口，匹配真实 MOC3、CDI3、原始纹理。
- `delivery/POPY_neck_fixed.zip`：加载此包，旧 `POPY_hair_fixed.zip` 仅作为历史基线。
- `artifacts/neck_repair/report/index.html`：79 姿态参考/前后对比、误差热力图与完整数值。
- `delivery/POPY_neck_repair_report.zip`、`neck_converter_source.zip`、`SHA256_neck_repair.json`：可离线审阅与校验。

公开仓库只同步代码、文档和数值记录；角色资产、渲染图与模型二进制仍留本地。Blender MCP 本次无法连接，使用独立快照后台渲染，原始快照 SHA-256 保持 `b4d94421c820d52db5d66da08302062328035a27af4fac378b818072faacbaed`。

## 剩余限制

弯曲脖子使用小片支撑平面近似，极端头身组合及擦边处仍有误差；最差误遮挡为 138px，位于水平 -45°、俯仰 -30°、头身三轴同时偏转的组合。可进一步按重投影残差细分目标片和自适应加密裁剪权重，而不是整体增加关键形数量。

本轮仅生成并验证质量 MOC，旧平衡版 CMO3 **不包含本次脖子修复**。没有声称完成官方 Cubism Editor 验证。Blender 源几何和上一轮避碰工程未作新修改。
