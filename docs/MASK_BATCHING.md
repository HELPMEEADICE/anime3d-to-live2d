# 无损遮罩几何公共子表达式

本轮对上一轮逐位一致全身模型继续优化，输出独立的 `output/POPY_maskbatched/POPY.model3.json` 和 `delivery/POPY_fullbody_maskbatched.zip`。原模型、三维源工程和历史交付包保留。实际数据见 `benchmarks/popy/fullbody/mask_batch.json`；本地 DX12 图像报告在 `artifacts/mask_batch_final/dx12/report/index.html`，Vulkan 报告在 `artifacts/mask_batch_final/report/index.html`。

## 数学变换和适用条件

固定版本 Ayagami 的遮罩只取贴图 alpha，忽略来源 ArtMesh 的 opacity 和自身遮罩，保留其 visible 与背面剔除。当前 POPY 六张纹理的全部 alpha 都是 255。因此，一个遮罩是来源三角形屏幕覆盖的并集。例如多个遮罩都需要 `A ∪ B` 时，可以复用包含 A、B 全部原三角形的隐藏几何 U，再使用 `U ∪ C`。不减少三角形，不合并近似的轮廓，不改变屏幕像素采样。

编译器把遮罩集合视为集合表达式，用位集记录每个来源出现在哪些集合中，按“减少的绘制数 /（新增顶点数 + 每网格固定代价）”贪心选择二元公共表达式，并用惰性优先队列更新代价。辅助表达式可递归复用，累计新增顶点预算为 50,000，每个辅助 ArtMesh 不超过 60,000 顶点。相同 culling 才能合并。零预算合法；重复来源、非法 ID、空来源和不匹配计划被拒绝。

只按顶点数评分的首版新增 755 个辅助网格，将全部遮罩集合的理论源绘制总数从 82,894 降到 19,121；八轮 Vulkan 实测中位耗时改善，但平均数和 P95 回退。完整失败数据保存在 `benchmarks/popy/fullbody/mask_batch_initial.json`。最终候选将固定代价设为 1,024 个等效顶点，在约相同的 50,000 顶点预算下只需 425 个辅助网格，理论绘制总数为 19,532。它不是几何近似误差权重，而是需要针对运行时重新计时的成本模型。理论计数假设所有遮罩集合都需要重建，不代表逐帧实际 GPU 计数。

辅助 ArtMesh 位于既有单位投影父节点之下，opacity 为 0，不进入普通颜色绘制，但可作为遮罩来源。原生常量 Glue 在原程序完成后，依赖顺序将来源最终坐标复制到辅助顶点；源侧权重 0、目标侧权重 1、兼容性 1，不改写原始顶点。辅助三角形索引就是来源索引的精确拼接。采样 UV 固定在已确认完全不透明的纹理内部。

此方案减少未修改 Ayagami 内的遮罩来源 draw call，普通 Model Poser 直接加载新 MOC 即可使用。没有修改 Ayagami 源码、上传 AI 内容到其上游、降低纹理/遮罩分辨率、删除表情/动作、缩减参数域或将动画换成帧贴图。它不减少独立遮罩纹理数量；额外顶点与 Glue 会增加 CPU 成本，必须实测选择预算。

以下情况不能套用此恒等式：半透明 alpha、动态禁用来源、不同背面剔除、不同运行时的遮罩语义。编译时检查真实纹理与参数轴覆盖域，计划展开后验证来源多重集；实际 MOC 验证还逐姿态检查 visible、culling 和复制坐标。本项目只在固定版本 Ayagami 验收，**尚无官方 Cubism Core/Editor 验证，不提供本轮新 CMO3**。

## 实机验证

外部 Rust 程序通过公开 API 加载前后两份真实 MOC，检查原 ArtMesh 的顺序、UV、索引、剔除、参数定义、遮罩表达式的叶子多重集、求值后的深度/透明度/颜色/可见性。1,803 个参数组合包含 362 标准姿态、39 参数各 17 点、256 随机组合和 58 动作各 9 个时间点。原始顶点要求 float32 逐位一致，所有辅助坐标必须有限且复制误差为 0。

两份 MOC 以同一未修改 Ayagami、同一画布和完整尺寸遮罩重新渲染 362 个姿态，RGBA 所有通道要求完全一致。Blender 三维参考、原图和优化图放在同一报告中；这证明优化保留原有画面，不证明此前近似已经等同三维渲染。

性能测试单独运行，两次 ABBA 顺序，共八个独立进程，各有五帧预热和相同的 60 帧挥手/大笑/步行动作。统计参数设置至 GPU 完成，包含 CPU 求值、遮罩和颜色绘制、GPU 同步，排除图片下载/写盘。分阶段记录 prepare、编码、GPU 提交等待，并保留全部样本及模型 SHA256。桌面没有隔离，原生 Vulkan 测试不代表浏览器 WebGPU 帧率；长帧不能从报告中去掉。

## 复现

需要本地 POPY 全身与上一轮精确模式 IR/模型、固定版本导出器和运行时、完整参考姿态。路径、顶点预算和固定成本在 `config/mask_batch.json`。新机器先按主 README 和 `PERFORMANCE_OPTIMIZATION.md` 构建这些资产，公开仓库不含角色资源。

```powershell
$env:POPY_WGPU_BACKEND = 'dx12'
python -m popy.mask_batch_review all
```

依次构建验证器、生成公共表达式计划与独立 IR、导出真实 MOC、复制匹配的动作/表情、清点真实 MOC、验证 1,803 姿态、重新渲染前后 362 姿态、独立重复计时、生成带输入指纹的报告、运行测试和打包。导出需要 JDK 26 和足够内存，默认 JVM 堆上限 20 GiB；`JAVA_HOME`、`JAVA_OPTS` 可配置。分阶段支持 `build|rig|export|inventory|validate|images|benchmark|report|test|package`。报告拒绝使用与当前模型、计划和姿态指纹不符的缓存证据。打包要求完整测试通过，且本次整帧中位数、平均数和 P95 均改善；不满足时保留实验数据并停止推荐包生成。

设置 `POPY_WGPU_BACKEND='vulkan'` 可单独重跑 Vulkan 对照；未设置时保留宿主自动选择。DX12 结果保存在独立子目录，不覆盖 Vulkan 证据。两种后端共用同一份 MOC，原生 CPU 顶点证明与后端无关。本次 DX12 复用了相同 MOC 指纹的 1,803 姿态证明，另行重做同一后端下的全量图片与计时。

低层 `python -m popy.mask_batch plan --budget 200000` 可生成其他预算的研究计划；`compile --budget 200000 --out artifacts/mask_batch/rig` 将其编译为独立 IR。预算越大不保证越快，不能把理论 draw call 减少直接当作整帧提升。

低层 `--helper-penalty 1024` 为固定网格成本。验证器另支持 `POPY_WGPU_BACKEND=dx12|vulkan` 的明确后端选择；这是本项目宿主的配置，不改动 Ayagami。不同后端的计时应单独比较，不能互相混算；改变后端后应重跑同一后端下的前后图片和计时。

可在不含角色资源的环境运行数学与输入约束测试：

```powershell
python -m unittest discover -s tests -p test_mask_batch.py -v
```

## 后续瓶颈

仍有 1,490 个独立遮罩集合与密集的原生骨架/面部计算。下一步应研究保留相同屏幕像素栅格的整数边界裁剪、遮罩图集和精确失效传播；这些需要独立运行时适配及与标准渲染器的像素回归。带残差的骨架/面部曲面拟合也值得继续，但不能以未经验证的低阶近似替代原遮挡细节。

## Vulkan 实测（2026-11-04）

RTX 5080 Laptop GPU，768×1024，两个 ABBA 块，每个版本共 240 个有效整帧样本。

| 参数设置至 GPU 完成 | 原逐位一致版 | 遮罩批处理版 |
|---|---:|---:|
| 中位数 | 195.74 ms | 164.20 ms |
| 平均数 | 281.96 ms | 271.53 ms |
| P95 | 340.50 ms | 327.14 ms |
| 最大值 | 3,265.91 ms | 3,445.41 ms |

常态帧变快，但极端长帧并未消除，最大值还有回退。平均数和 P95 的本次改善幅度较小，不能视作已经稳定解决卡顿。完整原始样本在 `mask_batch_vulkan.json`。

## DX12 实测与交付校验

同一台机器、同一份模型、同一画布和动作序列，另外运行两个 ABBA 块，每版 240 个有效样本。后端之间不能直接作优化前后比值。

| 参数设置至 GPU 完成 | 原逐位一致版 | 遮罩批处理版 |
|---|---:|---:|
| 中位数 | 256.28 ms | 212.49 ms |
| 平均数 | 255.74 ms | 211.68 ms |
| P95 | 279.95 ms | 225.54 ms |
| 最大值 | 308.33 ms | 258.66 ms |

DX12 中位数/平均数/P95 分别下降约 17.08% / 17.23% / 19.43%，本次未见 Vulkan 的数秒长帧；它的常态帧仍比 Vulkan 慢，不能仅以这个短测试保证永不卡顿。浏览器 WebGPU 未测速，也未达到稳定实时性能。

真实 MOC 清点为 5,875 ArtMesh、686,971 顶点、804,842 三角形（包含隐藏载体），10 个变形器、深度 3、5,439,788 个 ArtMesh 关键形、360,242 Glue 和 3,213,851 个 Glue 关键形。39 参数、58 动作、24 表情、六张 2048² 纹理保持原值；92 个既有资源文件字节一致。MOC 563,838,720 字节，比原逐位一致版增加约 0.30%。

104 项 Python 与 7 项 Rust 测试通过。交付 ZIP 已核对 CRC、MOC SHA256 和全部 90 个运行时资源引用。原始 `.blend` 指纹保持不变。模型与角色图像仅留本地，公开仓库同步代码、配置、研究记录和数值证据。
