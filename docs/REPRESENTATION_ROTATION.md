# POPY 无损通道分解与 MOC3 存储压缩

本页记录可选旋转载体候选，不是默认版。文件为 `delivery/POPY_fullbody_factored.zip`，本地模型为 `output/POPY_factored/`。CPU/同设备交替计时改善，但独立进程整帧退步，未替换默认包。决策及所有性能记录见 [汇总](REPRESENTATION_OPTIMIZATION.md)。原始工程和资产保留，没有新 CMO3，没有修改 Ayagami。

文件减少约 **43.28%**，ArtMesh 主关键形减少约 **73.55%**。这不等于全部类型关键形减少同样比例：新的 scalar Part 表仍有 2,561,935 行，Warp 表有 145 行，Rotation 表有 41,429 行，ArtMesh 表另有 838 行 BlendShape 数据。通道分解保留了必要的绘制顺序函数；没有把表搬到另一个文件后宣称删除。

Anon 的小文件来自另一种绑定结构，不能把它的约 4.6 MB 当作当前 POPY 密集三维投影程序可直接达到的无损体积。只读取本地 Anon 的统计，没有复制模型、纹理、曲线或绑定。

## 实际算法

1. 对每个 `(mesh, vertex)` 分析第一条 Glue 读写。只有在任何读取前，被兼容性 1、目标权重 1、源权重 0 的独立端点拷贝覆盖，初始几何才被证明没有用途。含 BlendShape 的对象暂不参与通道分解。
2. 对所有初始顶点均无用途的 2,810 个对象，把原来的密集几何网格换成一个静态关键形。原始参数轴和每个 float32 绘制顺序值进入非离屏 Part。
3. 同一组织 Part 内，仅相邻且排序函数完全相同的对象合成一个绘制组；不相邻的组可以复用 scalar Part，但在原位置分别出现，保留稳定排序。原组织 Part 成为新增 Part 的父节点，保留显隐及透明度语义。
4. 原来的浮点权重和可能并非数学上恰等于 1，不能直接删掉它们对透明度/颜色的影响。以相同参数轴共享 63 个零缩放 Rotation，保留这段原始浮点程序及参数失效依赖。旋转角和位置也为零，初始几何随后仍由原 Glue 覆盖；以矩阵运算替代了无用的逐顶点 Warp 插值。
5. 对头部原有的 Warp → Rotation → Rotation 祖先链建立三个仅计算原外观函数的 Rotation 代理，维持原来的浮点混合与乘法层级。不能简单把 Rotation 挂在 Warp 下：固定运行时的旋转几何计算还会应用 Warp 父节点。另将 1,422 个同样已证明初始几何无用的静态辅助网格接到外观代理上，避免它们继续做完整头部 Warp。这项处理只针对本导出桥明确创建的祖先结构，不是对任意未知工程的通用层级替换。
6. 导出后，对不可变位置块和 multiply/screen 联合颜色行按原始位模式建立共享池。约 148 万颜色行仅有两种联合值，仍保留所有原通道引用。
7. 通过未修改运行时的公开 API 遍历所有主关键形及 BlendShape 行，记录位置数据的实际读取长度。相同起点取所有所有者所需长度的最大值，只裁掉读取范围之外的填充。保留 float32、原顶点和三角形；不量化、不减面、不降低纹理或遮罩分辨率。

位置池的两个处理阶段有顺序：先合并完整填充块，再裁掉共享块的无用尾部。直接先裁尾部也可保持数值正确，但会漏掉不同长度所有者之间的共享，本模型会多约 1.3 MB。最终位置池从 60,694,928 个 float 降到 50,257,652 个，剩下约 201 MB 的 float 数据仍是真实成本。

`moc_pack.py` 只支持本项目已审计的 little-endian MOC3 v5 布局，不是通用格式转换器。它检查输入版本、保留头、范围、颜色引用和被修改段的尾部；extent 记录绑定输入 SHA-256。不能把 UV 任意合并：运行时同时用其偏移确定 GPU 顶点布局。

## 质量和性能证据

最终 MOC SHA-256：`eb0ca4e654790829fad8cdbf3b245f0edbec9c9c24b4261a40e97e016e88b88d`。

1,803 个真实运行时姿态包含原 362 个回归、39 参数连续值、随机复合值和全部 58 动作的连续采样，合计 **1,238,608,713** 个原始顶点比较。顶点位模式、外观浮点值、有效深度、可见根绘制序列全部零差异；原 Glue 字段、pair、顺序保持原样。DX12 的 362 个全分辨率 RGBA 渲染全部逐像素一致。参考使用既有 Blender albedo 评估条件；原模型已有的误差仍然保留，不能据此宣称 MToon 光照或全部未知参数组合已获官方验证。

前后各四个独立进程、每个 5 帧预热加 60 帧测量，以 ABBA 顺序执行两轮，GPU 完成计入整帧。完整时间、进程树 RSS、输入指纹和逐姿态结果位于 `benchmarks/popy/fullbody/representation.json`。这是本机原生 DX12 的结果，不能当作浏览器 WebGPU 或官方 Cubism Core 的测试。

**不能把本轮说成已解决所有 Glue 卡顿。** 默认版的 360,242 个 Glue 仍然存在。帧耗时是否改善必须读独立实测，不能由文件缩小比例推导。前一版 Warp 存储候选的平均耗时仅改善约 3.7%、P95 退步，已作为独立历史数据保留；不能将那版的聚合中位数改善当作稳定提速。

## 已运行但未作为默认交付的数学实验

- `glue_arena.py`：把确定初始值无用的寄存器放入有容量上限的图着色 arena，保留所有读写依赖，再按相同端点和字段批处理，末尾拷回原对象。5,125 个寄存器对象进入 12 个 arena，Glue 360,242→342,166，但多出 670,518 个输出拷贝 pair。独立程序轨迹证明和 5 姿态逐位检查通过；单轮 DX12 中位约 214.29 ms，比邻近基线约 201–206 ms 更慢，因此不交付为默认优化。
- 仅骨架常量因式分解再 arena：Glue 降到 229,542，单轮中位约 193.52 ms。这只是一轮性能探针，新增组合尚未完成全部 1,803/362 验收，**不是当前交付模型**。较早的独立骨架精度版有 Blender 几何证据，不能挪作本组合的验证。
- `point_graph.py`：构建不可变点表达式 DAG，按位相同输入和表达式作 CSE、去除不可观察节点。保留自插值的审计模式仍有 1,097,948 个活节点，最大深度 2,659。只在实数语义下折叠自插值后为 526,433 节点、深度 71，但移除了 476,539 次可能舍入的自插值。两者目前都是计算图审计；端点恒等式也还需核对 signed zero，**没有伪称为已导出的无损模型或浮点等价证明**。

这里的关键陷阱是 `lerp(A,A,t)` 在浮点算术中仍可能舍入；不能因为源端 pair 权重为零，就当作完全只读。下一项最有价值的工作是将头部/表情从密集屏幕空间张量重建为共享的三维骨骼局部投影基，并保留遮挡边界与表情耦合残差；应逐个用真实 Blender 投影和现有遮挡回归验收，而不是按任意 SVD 阈值删掉残差。

## GitHub 研究及复用范围

- [Cubism 官方性能说明](https://docs.live2d.com/en/cubism-editor-manual/performance/) 解释多参数组合如何增加插值及文件成本，也提出层级和 BlendShape 的建模方向。本项目据此检查参数乘积，没有用减少控制范围替代优化。
- [PSD2Live](https://github.com/tsunehimatoi/psd2live) 继续作为固定版本的格式导出依赖；通道分解结果直接构建 PuppetModel，没有走 PSD 默认二维自动绑定。适配器对父层级和 scalar Part 的新增支持属于 `exporter/` GPL 边界。
- [stretchystudio 的导出文档](https://github.com/MangoLion/stretchystudio/blob/master/docs/live2d-export/CMO3_FORMAT.md) 提供工程结构研究参考，不是已经在 POPY 上验证的优化器，本轮未引入其实现。
- [LIVE2D-MOC3](https://github.com/loliRuriruri/LIVE2D-MOC3) 的公开 README 描述读取、IR、层级和关键形恢复阶段；未把它当作能重写本模型的压缩器，也未引入依赖。
- [PurismCore](https://github.com/SakuraMotion/PurismCore) 是另一个兼容运行时的候选研究对象，尚未用本模型做对照或替换当前验证器；不能把换运行时当成已有 MOC 体积优化。

没有发现并实测一个能直接把本 POPY 密集关键形和原生 Glue 程序无损压到约 5 MB 的现成工具；这不是对所有 GitHub 项目的穷尽性结论。

## 复现

需要本机的 POPY 遮罩批处理 IR、完整资产、362 姿态参考及已安装工具链；公开仓库不分发角色数据。Windows 上执行：

```powershell
$env:POPY_REPRESENTATION_CONFIG='config/representation_rotation.json'
python -m popy.representation_review all
```

配置见 `config/representation_rotation.json`，阶段可分别调用 `build|rig|export|pack|validate|images|benchmark|test|report|package`。`all` 隔离每阶段进程，监测耗时与进程树峰值 RSS，避免大型 IR/JVM 分配在阶段之间滞留。输入 MOC、配置、用例、计划及运行时资源均绑定 SHA，完整验收不足时拒绝打包。严格通道优化由 `order_factor.py` 完成；外部 Rust 程序 `position_extents` 与 `hierarchy_equivalence` 提供实际读取范围和运行时回归。`moc_pack.py`、中立 IR 处理和独立测试工具使用本项目 MIT 许可，未复制 GPL 写入器的实现；GPL 导出器和依赖边界见 [THIRD_PARTY.md](THIRD_PARTY.md)。官方 Cubism Core/Editor 兼容性及浏览器性能仍需单独验证。
