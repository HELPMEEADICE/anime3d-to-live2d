# VTS 后续无损优化第二轮

以 `POPY_VTS_Exact` 为唯一质量与性能对照，输出 `delivery/POPY_VTS_Exact2.zip`。不重新拟合，不改变贴图、参数范围或遮罩分辨率；第一轮性能版已有的动作误差仍保留。此次是小幅增益，不重复使用早期 563 MB 模型作为基线夸大收益。

## 三项可证明的消除

1. **不可观察的网格**：只移除全部主关键形和 BlendShape 透明度恒为零、没有被任何遮罩引用、自己也没有遮罩的网格，共 84 个。保留有遮罩的透明目标，避免改变同上下文其他目标的包围范围。
2. **永远零面积的图元**：仅删除索引中至少两项相同的三角形，共 43,292 个。不是根据某个姿态的面积阈值减面。重复索引在所有参数下读取同一顶点，始终没有覆盖面积。保留全部对应顶点，因此目标/来源包围范围不变；若整个网格退化，仍保留一个原退化图元，维持非空索引状态。
3. **隐藏遮罩来源合批**：只将所有参数下透明度恒零、自己没有遮罩、几何插值轴/BlendShape 程序/父级/纹理/剔除一致的来源合并。它们必须在**每一个**使用它们的来源列表中连续、同序、同时出现。遇到外来来源、不同上下文用户、反序或超过 60,000 顶点均不合并。20 条来源链经顶点上限分段后省去 75 个 ArtMesh。隐藏来源的主画面深度没有用途，可统一为首成员的曲线；遮罩实际三角形顺序保持。

原有精确位置/颜色共享和不可读尾部裁剪继续使用。没有删除或合并任何遮罩上下文，前后均 80 组；牙齿局部遮罩保留。

## 独立核对

Rust 检查器通过固定、未修改的 Ayagami 公共 API：

- 要求删除对象的**真实 MOC** 中所有主/BlendShape 行透明度为零，且无任何遮罩依赖或自身遮罩。
- 将新遮罩来源链展开回原成员，逐目标核对完整来源顺序，拒绝额外覆盖或顺序改变。
- 验证每个删除的图元确实重复索引，剩余图元顺序不变；完整检查 UV、材质、剔除和透明度。
- 每个保留原网格映射到合批后连续顶点片段，映射必须无缺口、无重叠且覆盖全部输出；只对经过恒零证明的隐藏来源忽略深度差异。

实际运行 **1,803 姿态，307,759,479 次保留顶点比较，位模式零差异**；362 个全分辨率 RGBA 渲染逐像素一致。贴图、动作、表情、显示信息等运行时资源字节摘要一致。输入 MOC、映射、用例和资源摘要在验证开始/结束检查，并在打包时再次匹配，拒绝用旧证据打包修改后的输入。没有官方 Cubism Core、Editor 或 VTube Studio 实机验收。

## 本机性能

| 指标 | 前一无损版 | 第二轮无损版 |
|---|---:|---:|
| MOC 字节 | 89,307,200 | 88,302,400 |
| ArtMesh | 2,800 | 2,641 |
| 主 ArtMesh 关键形 | 111,255 | 108,270 |
| 顶点（含遮罩） | 173,000 | 170,693 |
| 三角形（含遮罩） | 195,441 | 149,318 |
| CPU Driver 中位数 | 2.223 ms | 2.108 ms |
| 参数设置至 GPU 完成中位数 | 32.276 ms | 31.085 ms |
| 同指标 P95 | 37.215 ms | 35.945 ms |
| 重复单模型进程峰值 RSS 中位数 | 458.76 MiB | 453.45 MiB |

RTX 5080 Laptop GPU，原生 DX12，固定 Ayagami `0d1d7aa3efe57b1b363b72e672e353c52a9c15d6`。CPU、GPU 都是同一 60 姿态交替执行 4 轮，每模型预热 5 帧，各 240 个计时样本。GPU 包含提交/同步，不含 PNG 下载写盘。桌面未隔离，前后两模型在配对性能测试中同时驻留。

内存另以 **ABBA BAAB** 次序启动 8 个独立单模型进程，每进程相同 65 姿态，正常渲染与 GPU 同步但不下载或写 PNG，进程加载/预热也计入峰值。前版四次范围 458.42–463.43 MiB，新版 452.32–454.02 MiB。重复内存收益约 **1.2%**，CPU 中位耗时约 **5.2%**，完整帧约 **3.7%**。

单次 362 图像回归曾记录 663.60→531.39 MiB；这些包含下载、图像处理及驱动瞬时分配，不能据此宣称稳定减少约 20% 内存。原始数值保留在报告中，结论采用上述重复单模型样本。也不将上一轮其他进程的 33.8 ms 与本轮 31.1 ms 混成新的配对性能结论。

原始数据见 `benchmarks/popy/fullbody/vts_exact2.json`，本机证据在 `artifacts/vts_mask_exact/`。这里测量的是原生 Ayagami，不是 VTube Studio 的 FPS、内存或兼容性。其余成本仍集中于 80 组遮罩及逐帧生成；本次不对加载器或上游运行时做修改。

## 复现与安装

需要前一无损版及其 IR、原固定依赖、JDK 和回归用例；公开仓库不分发角色资源：

```powershell
cargo build --release --locked --manifest-path rust/Cargo.toml -p popy-validate --bins
python -m popy.vts_mask_exact all
```

可分阶段执行 `rig|export|validate|memory|report|package`。MIT 几何与存储工具调用独立 GPL 导出器，许可边界不变。运行时入口仍为 `POPY.model3.json`，放入 VTS 的 `VTube Studio_Data/StreamingAssets/Live2DModels/`；继续使用 256 masks、每组至少 512×512。39 参数、58 动作、24 表情及牙齿修复保留；合并内部 ArtMesh 后，用户此前逐 ArtMesh 的特效设置可能需要重设。没有新 CMO3。前一包保留可回退。
